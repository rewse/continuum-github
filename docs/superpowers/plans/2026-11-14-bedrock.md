# Kiro CLI から Amazon Bedrock への切り替え 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sync` と `report` アクションが Kiro CLI の代わりに Bedrock の Converse API でモデルを呼び、`bedrock-model-id` が空のときと呼び出しが失敗したときは、モデルを使わない形の issue とレポートを作る。

**Architecture:** `kiro.py` を `bedrock.py` に置き換え、`Bedrock.ask(prompt, purpose, resources)` が boto3 の `converse` を 1 回呼ぶ。設定の `bedrock_model_id` が `None` なら CLI はモデルを作らず、節、要約、HTML を飛ばす。失敗した項目は、見出しのない issue 本文、要約のない重大度、HTML の行のないレポート本文になる。

**Tech Stack:** Python 3.13、boto3（`bedrock-runtime`）、botocore の `Config`、pytest、GitHub Actions の composite action、CloudFormation

**Spec:** `docs/superpowers/specs/2026-11-14-bedrock-design.md`

## Global Constraints

- 入力 `kiro-api-key`、Kiro CLI のインストール、`KIRO_API_KEY`、`KIRO_CLI`、`KIRO_MODEL` をすべてなくす。
- 入力 `bedrock-model-id`（既定 `""`）と `bedrock-region`（既定 `""`）を両方のアクションに足す。環境変数は `BEDROCK_MODEL_ID` と `BEDROCK_REGION`。空の `BEDROCK_MODEL_ID` はオフ、空の `BEDROCK_REGION` は `AWS_REGION` と同じ。
- docs で勧めるモデル ID は `us.anthropic.claude-sonnet-5-5`。コードに既定のモデルは置かない。
- boto3 の `Config` は `read_timeout=600`、`retries={"mode": "standard", "max_attempts": 3}`。独自の再試行は書かない。
- `converse` には `toolConfig` を渡さない。`system` は今の `SYSTEM_PROMPT`。
- 失敗のログは標準エラーへの 1 行 `model_failed purpose=<purpose> reason=<reason>` だけ。プロンプト、応答、例外のメッセージは出さない。
- フォールバックの注釈の文面は、issue が `_Bedrock could not write the Summary, Why it matters, and Risk if left unresolved sections, so this issue shows the scanner's details only. A later sync tries again._`、週次レポートが `_Written without Bedrock this week: <items>._`（`<items>` は `High summary`、`Medium summary`、`Japanese visual report` のうち書けなかったものを `, ` でつないだもの）。オフのときは付けない。
- プロンプトの文面、マーカー、JSON の形、文字数の上限（`MAX_SECTION = 1500`）、HTML の書き直しを 1 回だけ行う流れは変えない。
- 公開リポジトリなので、例の値は `111122223333`、`example-org`、`example.com` だけを使う。
- 検証: `uv run pytest -q` と `uvx --with pre-commit-uv==4.3.0 pre-commit@4.6.2 run --all-files`。新しいファイルは先に `git add` する。`.ruff_cache` と `__pycache__` は消してから走らせる。
- push、タグの push、`make release-minor` は所有者の確認を取ってから行う。

- `BEDROCK_MODEL_ID` が空のとき、`continuum-scan sections` と `report build` が boto3 のクライアントを一度も作らない（Task 1）。

class FakeClient:
    def __init__(self, response=None, error=None):
        self.response, self.error, self.calls = response, error, []

    def converse(self, **kwargs):
        self.calls.append(kwargs)
        if self.error:
            raise self.error
        return self.response


def _response(text, stop="end_turn"):
    return {"output": {"message": {"content": [{"text": text}]}}, "stopReason": stop}


def test_ask_calls_converse_without_tools_and_extracts_the_answer(tmp_path) -> None:
    skill = tmp_path / "SKILL.md"
    skill.write_text("skill body")
    client = FakeClient(_response("x <<<CONTINUUM-BEGIN>>>\nhello\n<<<CONTINUUM-END>>>"))
    assert Bedrock(client, "m1").ask("the question", "page", [skill]) == "hello"
    (call,) = client.calls
    assert call["modelId"] == "m1"
    assert call["system"] == [{"text": SYSTEM_PROMPT}]
    assert "toolConfig" not in call
    assert call["inferenceConfig"] == {"maxTokens": 32000}
    (message,) = call["messages"]
    assert message["role"] == "user"
    (block,) = message["content"]
    text = block["text"]
    resource = '<resource name="SKILL.md">\nskill body\n</resource>'
    assert text.index(resource) < text.index("the question")


def test_ask_logs_only_the_error_code_on_client_errors(capsys) -> None:

        {"Error": {"Code": "ThrottlingException", "Message": "secret finding text"}},
        "Converse",
    )
    assert Bedrock(FakeClient(error=error), "m1").ask("p", "summary") is None
    assert capsys.readouterr().err == (
        "model_failed purpose=summary reason=ThrottlingException\n"
    )


def test_ask_logs_the_class_name_on_botocore_errors(capsys) -> None:
