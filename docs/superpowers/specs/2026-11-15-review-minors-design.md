# 全体レビューで先送りにした指摘の修正

## 目的

`2026-11-15-issue-hardening` の全体レビューで先送りにした指摘を、v0.4.1 の前に直す。利用者が次の方針を承認した。

## 方式

### 1. 切り詰めでコードスパンが割れる

`issue_body` と `fit_body` は、詳細の本文を無害化したあとで文字数で切る。切る位置がコードスパンの途中だと閉じのバッククォートが消え、コードとして無害化を飛ばした範囲が GitHub では段落として描画されて、mention が効く。

切る位置を、上限の手前の最後の改行（`\n` か `\r`）の直後に下げる。コードスパンは 1 行の中だけなので、行の境目で切ればスパンは割れない。フェンスの途中で切れた場合は、GitHub でも閉じていないフェンスとして最後までコードになるので、mention は効かない。上限の手前に改行がなければ詳細の本文を空にし、`… (truncated)` だけを残す。

比べた案として、生のテキストを先に切ってから無害化する方法がある。`fit_body` は既存の本文（元のテキストがない）も切るので、それだけでは足りないため採らない。

### 2. `Retry-After` が日付形式

`_retry_delay` は `Retry-After` を秒数として読み、読めなければ 60 秒にしている。HTTP は日付形式も認めるので、秒数として読めなければ `email.utils.parsedate_to_datetime` で日付として読み、今の時刻との差を待つ。日付としても読めなければ `X-RateLimit-Reset` を見て、それもなければ 60 秒にする。`X-RateLimit-Reset` が数値でない場合も 60 秒にする。

### 3. 過去の `X-RateLimit-Reset`

時計のずれで `X-RateLimit-Reset` が過去になると、待ちが 0 秒になり、3 回の再試行を 1 秒もかからず使い切る。レート制限の待ちの下限を 1 秒にする（`_MIN_WAIT = 1.0`）。上限の 15 分はそのまま。

### 4. `_is_rate_limited` の docstring

二次レート制限は `Retry-After` を付けずに 403 で返ることがあり、そのために本文の `message` でも判定している。この理由を docstring に書き、判定を削られないようにする。

### 5. 行をまたいで対になるバッククォート（全体レビューの指摘）

`escape_text` はバッククォートの列を行ごとに対にするが、CommonMark は段落の中なら行をまたいで対にする。`` `x\n`@b` y `` では、無害化側は 2 行目の `` `@b` `` をコードとみなして手を付けないが、GitHub は 1 行目の `` ` `` と 2 行目の最初の `` ` `` を対にするので、`@b` は段落として描画されて mention が効く。行ごとの判定は CommonMark より狭いとは限らない。

空行で区切った段落ごとに、すべての行で、バッククォートの列が同じ行の中で対になっているかを調べる。すべて対になっていれば、CommonMark も同じ対を作るので、今までどおり行ごとにコードスパンを残す。1 つでも同じ行の中で対にならない列があれば、その段落は全体をコード以外として扱い、コードスパンの中の mention と画像も置き換える。直前に `\` があるバッククォートの列も同じ扱いにする。CommonMark はコードスパンの外の `` \` `` を普通の文字にするので、対の作り方が変わるからである。コードスパンの中に `&#8203;` などが見えることはあるが、mention と画像は効かない。

すべての列が同じ行の中で対になる段落では、CommonMark も左から順に最も近い同じ長さの列と対にするので、行ごとの対と同じになる。

この規則のもとでも、コードスパンを残す段落ではスパンは 1 行の中にあるので、1 の行の境目での切り詰めはスパンを割らない。

`inline=True` の場合も、テキスト全体を 1 つの段落として同じ規則を当てる。

GitHub で確かめると、行をまたいで対になる場合、mention は直前が `` ` `` なので効かないが、画像は `<img>` として描画される。

### 6. mention の直前の文字

mention の判定は、直前が英数字・`` ` ``・`/`・`@` のどれでもない `@` としていた。GitHub で確かめると、`x/@name` は mention になる。直前が英数字でない `@` をすべて置き換える（`(?<![A-Za-z0-9])@(?=[A-Za-z0-9])`）。`` `@name `` や `_@name` は GitHub では mention にならないが、置き換えても表示は変わらないので区別しない。メールアドレスは直前が英数字なので変わらない。

### 対象外

- 見出しの `⚠️`。`cliff.toml` の既存の見出しも spec も U+FE0F を付けており、揃っている。
- 利用側の WAF クライアントの 2〜4。同じ変更を利用側の仕様で入れる。
